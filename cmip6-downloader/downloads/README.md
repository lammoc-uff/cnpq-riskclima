# Downloads

Operational outputs use `source_id/experiment_id/table_id/variable_id/grid_label` below the resolved `DOWNLOADS_DIR`. Each group contains its catalog and log, `member-<member_id>.zarr` stores, and configured ensemble products. Zarr stores are written through locked sibling partial stores and promoted only after validation. Multiple members are removed when `CLEANUP_MEMBERS=true` only after all expected members and ensembles validate; a sole member is always retained. Errors before or during the cleanup rename phase preserve every `member-*` store. A later physical-removal failure can leave warned `.cleanup-*` paths for manual removal, but cannot leave a partial set of visible `member-*` stores.
